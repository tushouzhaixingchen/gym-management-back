# 会员端课程报名接口文档

## 📋 概述

本文档描述了会员端课程报名相关的所有接口，包括角色隔离和支付成功后自动更新课程报名人数功能。

## 🔐 角色隔离

所有会员端课程报名接口都使用了 Spring Security 的 `@PreAuthorize("hasRole('MEMBER')")` 注解进行角色隔离，确保只有 **MEMBER（会员）** 角色的用户才能访问这些接口。

### 2. 报名课程

**接口地址：** `POST /api/member/courses/book`

**权限要求：** 仅 MEMBER 角色可访问

**请求头：**
```
Content-Type: application/json
Authorization: Bearer {token}
```

**请求体：**
```json
{
  "courseId": 1,
  "remark": "我想参加这个课程"
}
```

**请求参数说明：**
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| courseId | Integer | 是 | 课程 ID |
| remark | String | 否 | 备注信息 |

**业务逻辑：**
1. ✅ 检查课程是否存在
2. ✅ 检查课程状态（是否已满、已取消、进行中、已结束）
3. ✅ 检查会员是否已报名该课程（防止重复报名）
4. ✅ 检查剩余座位数
5. ✅ 创建报名记录（初始状态为未支付）
6. ✅ 生成报名单号（格式：CB + 时间戳 + 会员ID）

**响应示例：**
```json
{
  "code": 200,
  "message": "报名成功",
  "data": {
    "id": 1,
    "bookingNo": "CB20260510170000001",
    "courseId": 1,
    "courseName": "瑜伽初级班",
    "price": 100.00,
    "status": 0,
    "statusText": "已报名",
    "payStatus": 0,
    "payStatusText": "未支付",
    "createdAt": "2026-05-10T17:00:00"
  }
}
```

**错误响应：**
```json
{
  "code": 400,
  "message": "课程已满，无法报名"
}
```

### 3. 支付课程报名 ⭐

**接口地址：** `POST /api/member/courses/bookings/{bookingId}/pay`

**权限要求：** 仅 MEMBER 角色可访问

**请求头：**
```
Content-Type: application/json
Authorization: Bearer {token}
```

**路径参数：**
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| bookingId | Integer | 是 | 报名记录 ID |

**请求体：**
```json
{
  "payMethod": 1
}
```

**请求参数说明：**
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| payMethod | Integer | 是 | 支付方式：1-微信，2-支付宝，3-现金 |

**业务逻辑：**
1. ✅ 查询报名记录
2. ✅ 校验是否已支付（防止重复支付）
3. ✅ 更新支付信息（payStatus=1, payTime, payMethod）
4. ✅ **【核心功能】课程的 booked_seats + 1**
5. ✅ 如果报名后已满，更新课程状态为已满（status=0）
6. ✅ 保存到数据库

**响应示例：**
```json
{
  "code": 200,
  "message": "支付成功",
  "data": {
    "id": 1,
    "bookingNo": "CB20260510170000001",
    "courseId": 1,
    "courseName": "瑜伽初级班",
    "price": 100.00,
    "status": 0,
    "statusText": "已报名",
    "payStatus": 1,
    "payStatusText": "已支付",
    "payTime": "2026-05-10T17:05:00",
    "payMethod": 1,
    "payMethodText": "微信"
  }
}
```

**错误响应：**
```json
{
  "code": 400,
  "message": "该报名已支付"
}
```

## 🎯 核心功能说明

### 支付成功后自动更新课程报名人数

在 `payCourseBooking` 方法中，当支付成功后会自动执行以下操作：

```java
// 5. 【关键】支付成功后，课程的 booked_seats +1
course.setBookedSeats(course.getBookedSeats() + 1);

// 6. 如果报名后已满，更新课程状态为已满
if (course.getBookedSeats() >= course.getMaxSeats()) {
    course.setStatus(0); // 0 表示已满
}

courseRepository.save(course);
```

**数据库影响：**
- 表：`courses`
- 字段：`booked_seats` 自动 +1
- 条件：支付成功后（payStatus = 1）

## 🔒 安全性

### 角色隔离实现

所有接口都使用了 Spring Security 的注解进行角色隔离：

```java
@PreAuthorize("hasRole('MEMBER')")
public ResponseEntity<Result<...>> methodName(...) {
    // 只有 MEMBER 角色可以访问
}
```

### 用户身份验证

通过 JWT Token 从 SecurityContext 中获取当前登录会员的 ID：

```java
private Integer getCurrentMemberId() {
    Object principal = SecurityContextHolder.getContext()
            .getAuthentication().getPrincipal();
    
    if (principal instanceof Integer) {
        return (Integer) principal;
    } else {
        throw new BusinessException(ResultCode.UNAUTHORIZED);
    }
}
```

## 📊 数据流程

```
会员报名流程：
1. 会员调用 POST /api/member/courses/book
   ↓
2. 系统创建报名记录（course_bookings 表）
   - status = 0 (已报名)
   - payStatus = 0 (未支付)
   ↓
3. 会员调用 POST /api/member/courses/bookings/{id}/pay
   ↓
4. 系统更新支付信息
   - payStatus = 1 (已支付)
   - payTime = 当前时间
   ↓
5. 系统更新课程报名人数
   - courses.booked_seats + 1
   ↓
6. 如果人数已满，更新课程状态
   - courses.status = 0 (已满)
```

## 📝 注意事项

1. ✅ 所有接口都需要有效的 JWT Token
2. ✅ 只有 MEMBER 角色可以访问这些接口
3. ✅ 同一个会员不能重复报名同一个课程
4. ✅ 支付成功后才会增加课程报名人数
5. ✅ 课程满员后会自动更新状态为"已满"
6. ✅ 所有操作都有完整的日志记录
